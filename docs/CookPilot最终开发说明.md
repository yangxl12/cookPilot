# CookPilot 最终开发说明

- 更新日期：2026-10-12
- 定位：手机端 AI 烹饪助手，帮助用户选菜、按步骤做菜，并保存自己的做法与心得。
- 开发依据：以当前 [demo.html](../demo.html) 的页面和交互为 UI 基准，以本文统一业务规则；历史文档与本文冲突时，以本文为准。
- Demo 中的意图识别、推荐、生成、问答和连接测试均为模拟；正式版本需要接入真实模型，不能将固定回复视为功能完成。

## 1. 首版范围

围绕“一次做一道菜”完成闭环：自然语言选菜 → 复用或生成指南 → 备菜与逐步烹饪 → 过程中求助、计时和记录心得 → 以后再次制作。

无需注册，用户自带模型 API Key；菜谱、制作记录、对话、偏好和模型配置保存在当前设备。支持多套模型配置，用户手动选择当前使用的模型。

首版不做多道菜统筹、账户与跨设备同步、社区、语音、图片识别、AI 配图、自动选择模型或离线 AI。后台和锁屏通知不作为首版保证。

## 2. 页面与导航

| 页面 / 入口 | 内容与主要操作 |
| --- | --- |
| 首页 `#home` | 输入需求、对话、候选选菜；顶部提供菜单、新建对话、模型选择、通用设置 |
| 左侧菜单 | 依次为 AI 菜谱、菜谱大全、我的厨房、对话历史；顶部提供全局搜索和关闭按钮 |
| AI 菜谱 `#ai-recipes` | 查看已生成指南和制作记录，搜索菜名、再次制作、删除 |
| 菜谱大全 `#recipes` | 搜索和分类浏览预置菜谱，选中后直接进入指南 |
| 全局搜索 `#search` | 跨菜谱、心得与有效对话搜索，支持来源筛选，返回或刷新后恢复搜索条件 |
| 烹饪指南 `#cook` | 准备首卡、烹饪步骤卡；心得、问问 AI、计时器、全部步骤 |
| 我的厨房 `#settings` | 管理模型配置、导出数据、管理本地数据 |

只有首页提供菜单入口。子页面通过返回按钮沿实际访问路径返回，例如“首页 → 菜谱大全 → 指南”逐级返回。浏览器前进、后退和刷新应保持路径；直接打开子页面时也能返回首页。

不设置全局底部 tabbar，不保留“我的指南”中间页，也不把 AI 菜谱和菜谱大全做成同页 tab。指南底部的步骤导航保留。

## 3. 主业务流程

```text
首页输入菜名 / 食材 / 模糊想法
  ├─ 完全无关做菜 → 普通聊天，可继续输入
  └─ 做菜相关 → 推荐几道菜，通常 3 道
       ├─ 选择已有 AI 菜谱 → 打开原版本及原制作记录
       └─ 选择新菜谱 → 完整生成并校验 → 自动入库 → 打开指南

菜谱大全选菜 → 使用预置指南建立制作记录 → 打开指南
AI 菜谱查看 → 打开原制作记录
AI 菜谱再做一次 → 沿用指定版本，建立新的制作记录

指南：准备首卡 ↔ 第 1 步 ↔ 第 2 步 ↔ …… ↔ 最后一步
      随时使用心得、AI 求助、计时器和步骤目录
```

### 3.1 首页对话与选菜

- 未发送时只展示“想做什么菜？”和输入框，位置、留白参考 Demo；不添加说明段落、快捷提示词或额外菜谱入口。
- 发送后展示用户消息和分析状态，标题栏固定顶部，输入区固定底部，中间消息可滚动。空白输入不能提交，分析和生成期间防止重复操作。
- 支持明确菜名、现有食材、模糊吃饭需求。完全无关做菜的内容正常聊天，不生成菜谱；意图不明确时通过对话澄清，不依赖单字判断。
- 候选展示菜名、预计时间、难度及已有版本标识，按钮区分“使用已有菜谱”和“生成菜谱”。先提供摘要，仅为最终选中的一道菜生成完整内容。
- 不增加独立条件确认页，不强制追问人数。默认常规一份菜；识别用户明确提供的主料数量、口味和限制。“一份菜”不等同于固定一人份。

### 3.2 已有复用与新菜谱入库

| 场景 | 业务规则 |
| --- | --- |
| 同一道菜已存在 | 按菜品身份和别名匹配，例如西红柿炒鸡蛋与番茄炒蛋；不能仅因共有食材就认定相同 |
| 选择已有菜谱 | 使用最近保存的匹配版本并明确展示版本，打开原制作记录，不重新生成、不重复入库 |
| 新输入与原版本不同 | 提示沿用原用量与做法，不静默覆盖原口味、用量、进度、心得或计时器；主动调整走确认流程 |
| 已有版本含当前忌口 | 显示冲突并阻止选择，引导选择其他菜；不自动生成同名副本绕过冲突 |
| 选择新菜谱 | 生成完整指南，校验成功后自动加入 AI 菜谱，同时建立首条制作记录并打开准备首卡，无需另点保存或等做完 |
| 重复点击、重试或并发返回 | 选择时和保存时均检查已有记录，同一生成任务只入库一次；已存在则转为复用 |
| 失败或取消 | 不保存半成品，保留原消息与候选以便重试；离开页面或新建对话后，旧任务不得延迟入库或跳转 |

### 3.3 通用设置与菜谱大全

通用设置从首页模型按钮右侧打开，包含忌口、口味两个自由输入项和锅具多选。保存后本机持久化，取消不修改。用于推荐筛选和之后新建指南的适配，不追溯修改已有指南；本次明确的口味、用量优先，忌口与过敏限制合并检查，冲突必须提示。

菜谱大全参考 Demo 的搜索框、分类按钮和列表行样式。搜索与分类同时生效，分类沿用“全部 / 中式 / 西式与日式”；点菜直接进入准备卡，不经过首页候选推荐，也不加入 AI 菜谱。

预置菜谱内容参考现有 [中外经典家常菜200道](./中外经典家常菜200道.md)，整理为食材、备菜和步骤等结构化内容后展示；Demo 的六道菜用于演示交互。新增制作记录可按当前偏好适配，不改写预置原文；无法满足限制时提示冲突。

### 3.4 烹饪指南

所有入口统一进入卡片页面。新生成、打开已有指南、选择预置菜谱、再次制作时展示准备首卡；刷新当前页面则恢复上次查看卡片。重新打开首卡不清空制作进度。

| 区域 | 内容与交互 |
| --- | --- |
| 顶栏 | 返回、菜名，以及按顺序排列的“心得 → 问问 AI → 计时器 → 全部步骤图标” |
| 准备首卡 | 固定顺序为要点 → 食材和调味辅料 → 备菜；主要食材、调味与辅料分别用表格展示，备菜可勾选并提供必要的计时和并行提示 |
| 后续步骤卡 | 每步一张卡，展示标题、动作、火候、本步用量、计时、完成信号和关键提醒；不需要的字段不占位 |
| 底部导航 | “准备 + 序号与步骤名”，点击直达；导航自身可横向滚动，切换后当前项尽量居中 |
| 卡片阅读 | 左右滑动切换，首尾不循环；相邻卡露边提示；长内容在卡内上下滚动，顶栏与底部导航保持可见 |
| 全部步骤 | 弹窗展示目录，选择后定位相应卡片 |

准备卡不占烹饪步骤编号，N 个步骤对应 N+1 张卡。卡片查看位置与实际执行记录分开保存，翻卡、跳转、保存心得或计时到点都不能推定步骤或整餐已完成。

不增加独立总览、器具展示区、大图、原理展开区、成品检查、评分、“保存这一餐”或整餐完成按钮。最后一步停留在原卡片；原理可用于 AI 按需解释，历史已有完成记录保留。

### 3.5 问问 AI 与流程调整

在准备或任意步骤打开问答弹窗，支持自由提问及 Demo 中的快捷问题，如“怎么判断熟了”“锅里出水了”。回答优先给当前能执行的操作、需要观察的状态及后续影响。

指南问答绑定当前制作记录，与首页选菜对话隔离。请求上下文包括当前菜谱版本、制作条件、当前阶段、已完成记录、相关问答和计时状态。准备卡使用“备菜阶段”上下文，不能误用上次查看的烹饪步骤；用户描述的实际进度优先，不能仅凭浏览位置判断已经做完哪些操作。

需要改做法时执行“展示建议和受影响步骤 → 用户确认更新 → 保存新版本及变更说明”。仅更新当前及后续尚未完成的相关步骤；准备阶段从第一条未完成步骤起判断。保留已执行内容、原历史版本、心得、进度与计时器，不重新生成整道菜。取消建议不产生修改。

确认后，本次制作引用新版本；其他制作记录继续引用各自原版本。调整涉及用量时，操作文案和本步用量必须一致；已使用用量保留原记录。

### 3.6 计时器

- 备菜和步骤中的计时由用户主动启动，也可在计时面板添加名称与时长；同一制作记录支持多个计时器。
- 计时关联制作记录及稳定的备菜 / 步骤标识，支持暂停、继续、取消；同一项已有有效计时时打开原计时，避免误触重复启动。
- 有计时记录时保留跨页面入口，运行中显示剩余时间，暂停或到点后也可重新打开；面板标明菜品与计时名称。
- 按截止时间计算剩余时间，刷新及回到前台时重新计算；暂停保存剩余时长。到点页面内提醒，由用户观察状态，不自动切步骤或标记完成。
- 返回列表、打开其他菜、编辑心得或再次制作都不清除原记录的计时器。

### 3.7 心得、查看与再次制作

心得绑定本次制作记录，准备和任意步骤都能编辑。弹窗回填已保存内容，支持多行纯文本、最多 2000 字及字数提示。保存覆盖当前心得，空文本可清空；取消、关闭、遮罩和 Escape 放弃未保存草稿。保存只改心得，不影响版本、进度或计时器；AI 不得覆盖心得。

AI 菜谱列表参考 Demo 展示菜图或占位图、菜名、制作条件、时长、心得摘要和版本，支持菜名搜索及空状态。

| 操作 | 结果 |
| --- | --- |
| 查看指南 | 打开原记录并展示准备首卡，保留已保存进度、心得和计时 |
| 再做一次 | 沿用选中记录的菜谱版本，创建新制作记录；勾选、进度、心得和计时为空，原记录保留，不重新调用完整生成 |
| 删除指南 | 二次确认后删除当前列表记录、其心得与关联计时器；不影响其他制作记录，仍被引用的菜谱版本不得误删 |

多次制作可保留独立列表记录。“同菜谱不重复生成”针对菜谱实体，不限制用户创建新的制作记录；无需另加完成或评分流程才能再次制作。

### 3.8 对话历史与全局搜索

新建对话清空当前输入和消息视图，取消未完成任务，旧对话保留；首次发送才创建历史，避免空记录。历史标题取首条输入，最多 28 字，按最后一次发送倒序并按今天、昨天、近 7 天、近 30 天分组。

点击历史恢复完整消息与候选，继续发送追加到同一对话；刷新恢复当前对话。仅查看不延长保留期。超过最后发送时间 30×24 小时删除，恰好 30 天保留；启动时及页面打开期间每分钟清理，关闭期间下次打开补清理。当前对话过期则回到首屏，已生成菜谱、心得和计时器不受影响。

菜单顶部搜索进入独立全局搜索页 `#search`，覆盖 AI 菜谱正文、条件、心得与版本变化，预置菜谱正文，以及有效历史的全部消息。按空格拆分关键词并同时匹配，忽略大小写；支持全部、AI 菜谱、菜谱大全和对话历史筛选，按来源分组展示数量、命中摘要与关键词高亮。点结果直接打开指南或恢复对话；搜索词与筛选条件保存在地址中，返回或刷新后恢复。空输入展示关键词建议和可搜索范围，无匹配时提供重新搜索或查看其他分类的入口。页头与搜索区域固定，结果随页面滚动；返回回到进入搜索前的页面。

### 3.9 模型与数据管理

模型配置包含名称、接口地址、API Key、模型名称，支持添加、编辑、删除、真实连接测试和切换。首版面向兼容统一对话接口的服务；配置名称、模型名称必填，地址须合法，Key 是否必填依服务而定。测试失败说明原因并允许重试，不能返回模拟成功。

首页和厨房中的模型选择保持一致，切换对后续请求生效；已发出的请求绑定发起时的模型。删除当前配置后选择剩余配置，没有可用配置时引导添加。缺少配置只阻止模型请求，已有指南、预置菜谱、心得和计时仍可使用。

数据管理支持导出 JSON、清除全部本地用户数据。导出包含菜谱版本、制作记录、心得、有效对话、计时、偏好和脱敏模型配置；API Key 默认隐藏，不进入导出、普通日志或菜谱内容。删除与清空需确认，清空不删除内置菜谱资源，也不能在刷新后自动补回示例用户记录。

“恢复演示数据”仅用于 Demo / 开发环境，正式版不展示此操作，首次使用不伪造用户的菜谱与对话历史。

## 4. 数据与 AI 内容约束

| 数据对象 | 应承载的内容 |
| --- | --- |
| 菜谱及版本 | 稳定菜品标识、名称与别名、来源、条件、食材、备菜、步骤、版本及变更说明 |
| 制作记录 | 引用菜谱版本，保存备菜勾选、查看位置、执行记录、心得和创建时间 |
| 计时器 | 引用制作记录及备菜 / 步骤，保存名称、运行状态、截止时间或暂停剩余时长 |
| 对话 | 标题、创建与最后发送时间、完整消息、推荐及所引用的菜谱标识 |
| 设置 | 通用偏好、多套模型配置、当前模型；敏感配置不混入业务内容 |

正式实现需要拆分菜谱版本与制作记录，不直接照搬 Demo 中将两者合并的 `Guide`。备菜和步骤使用稳定 ID，不能用卡片序号关联计时器。

AI 返回结构化内容，由固定组件渲染，不让模型生成整页 HTML。保存前检查必要字段、食材与步骤用量对应、准备先于使用、步骤依赖以及忌口和锅具限制；缺失或矛盾时重试或提示失败，不保存不可执行的内容。

保留已使用 Demo 数据时，旧指南与笔记须兼容迁移，笔记原文作为心得；旧总览 / 检查地址转入卡片页，旧列表地址转入对应独立页面。迁移不得清空用户记录或改变步骤、计时关联。

## 5. UI 实现基准

整体直接参考当前 Demo 的视觉与布局，复用 [原型样式 archive/demo/src/styles.css](../archive/demo/src/styles.css) 的设计参数，保持简洁、便于厨房阅读和点按。

| 项目 | 要求 |
| --- | --- |
| 尺寸 | 320–480px 手机布局；桌面最大宽度 480px 居中，不另做桌面信息架构 |
| 颜色 | 白底，主绿 `#28664e`，正文 `#24352e`，次要文字 `#69766d`，浅绿 `#eaf2ed`，分隔线 `#e8eeea` |
| 字体与层级 | 沿用 Demo 的 DM Sans 和中文系统字体；菜名、当前动作突出，辅助信息弱化 |
| 首页与列表 | 紧凑标题栏、浅色圆角输入、绿色主按钮；列表保持缩略图 / 图标、文字和分隔线的层级 |
| 指南 | 浅灰绿页面背景、白色圆角卡片、相邻卡露边；用量表和完成信号明确可读 |
| 弹层 | 菜单从左侧滑出，其他操作沿用 Demo 底部弹层；遮罩和关闭按钮可用，关闭后恢复入口焦点 |
| 适配 | 顶底安全区、软键盘及长文本不得遮挡输入和操作；窄屏顶栏不挤出屏幕，横向滑卡与纵向阅读互不干扰 |

减少重复标签和装饰文案；加载、成功、错误和空状态使用简短反馈。弹窗隔离背景操作，键盘可关闭；动态效果尊重减少动画设置。

## 6. 异常与验收

分析、生成、问答和连接测试都应有处理中、成功、失败状态。失败保留可重试内容；新建对话、导航或切换制作记录后，旧响应不能写入新上下文。刷新中的未完成请求标记为已中断，不能一直显示处理中。保存失败明确反馈并保留编辑内容，不伪装成功。

首版按以下场景验收：

1. 菜名、食材和模糊需求都能先选菜；无关问题能聊天，继续输入时上下文正确。
2. 已有菜谱及别名命中后直接复用；原版本、用量、进度、心得和计时不变，忌口冲突可见。
3. 新菜谱仅在选中并完整生成后入库；重复提交不重复保存，失败和取消不留半成品。
4. 两个菜谱页独立导航，预置选菜直接进入指南，查看和再次制作的数据互不覆盖。
