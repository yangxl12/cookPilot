# 性能检查与修复（2026-10-14）

检查覆盖正式应用的启动、数据订阅、搜索、菜谱列表、烹饪卡片、计时器、弹层、AI 请求生命周期、存储清理和 PWA。归档原型不参与正式入口与构建。

## 发现与处理

| 问题 | 修复 |
| --- | --- |
| 全局每秒刷新，即使没有运行中的计时器 | 独立计时组件刷新；暂停、完成和页面隐藏后停止刷新；恢复时按截止时间核对 |
| 任一表变更都读取八张表，15 秒租约心跳也刷新全库 | 每张表独立订阅；设置仅订阅三个业务键 |
| 首页常驻全部指南、对话与烹饪问答 | 首页只读当前对话和候选关联的最新版本；指南按版本读取，问答按制作记录读取，历史在打开时订阅 |
| 首页同步加载完整的 200 道菜谱和所有页面 | 页面与菜谱按需加载；AI 制作列表无需下载预置菜谱；下载失败保留重试入口 |
| 长列表一次创建数百行及图标 | 每个列表首批 24 行，接近末尾时自动补齐；搜索来源分别分批，搜索与数量始终使用完整集合；观察器随页面销毁 |
| 搜索每次输入重复拼接全文、小写转换、扫描版本和重建所有结果节点 | 构建全文索引，使用 Map/Set 查找；延后筛选和复用结果节点；离屏列表与卡片跳过绘制 |
| 每次滚动事件读取卡片宽度，滑动途中可能写入位置并打断滑动 | 尺寸在 ResizeObserver 中缓存；滑动停止后保存；旧浏览器使用可清理的防抖回退 |
| 页面退出时提示定时器和活动请求未完整清理 | 清理提示、取消请求及任务，移除事件监听；返回缓存页面时恢复租约 |
| 历史清理读取并反序列化完整对话 | 使用时间索引查过期主键；无过期数据时不写入 |
| 启动重写所有对话；旧文档租约不断累积 | 只修改需恢复的消息，事务清理失效租约；保留其他页面的活跃请求 |
| 开发初始化请求无超时；PWA 重复注册 | 私密配置读取限时 2.5 秒；由应用统一注册 PWA，仍预缓存全部离线资源 |

拆分订阅后，额外核对对话 ID 与版本 ID，避免切换期间使用上一条订阅结果。数据库实体和版本历史保持完整。

## 对比采样

使用本机 Chrome、390 × 844 视口、开发构建和独立浏览器上下文。相同数据：250 道 AI 菜谱、750 个版本、250 条制作记录、100 段各 40 条消息的对话、1000 条烹饪问答。私密配置请求被拦截，没有真实模型调用。堆内存采样前执行垃圾回收。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首页 JS 堆内存 | 22.4 MB | 8.8 MB |
| 首页空闲 3.5 秒 App / Home 渲染 | 各 4 次 | 0 次 |
| 一次租约写入引起的业务表读取 | 8 张表 | 0 |
| 十次翻卡引起的指南 / 对话 / 问答读取 | 各 10 次 | 0 次 |
| 首页同步依赖 JS 原始体积（正式构建） | 1150.10 KB | 约 484 KB |
| 4 倍 CPU 降速：打开 AI 列表的主线程任务耗时 | 2744 ms | 329 ms |
| 4 倍 CPU 降速：输入“测试菜2”筛选的主线程任务耗时 | 3316 ms | 268 ms |
| 4 倍 CPU 降速：输入“鸡蛋”搜索并显示全部来源的主线程任务耗时 | 1509 ms | 442 ms |

这是同机采样，耗时会受浏览器、开发模式和机器负载影响，不代表手机端的固定响应时间。PWA 仍在后台预缓存全部资源，约 1.2 MB；首页渲染不必等待菜谱下载与解析。

## 验证与复现

`npm run test:perf` 在已启动的根路径开发服务上创建独立浏览器上下文、写入合成数据并采样，结果写入 `.local/performance-after.json`。不修改正在使用的浏览器数据库。也可以执行 `node scripts/performance-audit.mjs before http://localhost:5174` 采样另一份开发服务上的旧代码。

回归测试覆盖：空闲和租约零刷新、计时更新局部化、隐藏与恢复后计时到期、翻卡保存与尺寸变化、200 道菜谱滚动补齐、未渲染记录仍可搜索、反复打开页面和弹层后的 DOM / 监听器 / 堆内存增长检查，以及原有业务、模型适配、迁移、手机布局和离线恢复。

57 项单元测试、27 项浏览器测试、根路径和 `/cookPilot/` 子路径的各 3 项 PWA 测试，并执行构建、格式和私密配置泄漏检查。模型服务的网络和推理耗时未作真实调用采样。
