# 烹饪指南开发说明

- 对应需求：REQUIREMENTS.md v0.5
- 更新日期：2026-10-12
- 用途：明确 Demo 与正式开发共用的交互和数据约定。

全局导航已改为左侧菜单抽屉，“我的指南”与“我的厨房”从菜单进入；首页固定布局与对话历史见 [页面结构与对话开发说明](./页面结构与对话开发说明.md)。本页的准备/步骤数字导航继续保留。

## 1. 页面结构与入口

烹饪指南只有一套卡片页面。新生成、选中预置菜谱、打开已保存指南、再次制作都直接展示准备首卡；刷新当前页面恢复上次查看位置。打开首卡只是切换查看位置，不重置实际制作记录。

```text
返回  菜名                 心得  问问 AI  计时器
┌──────────────────────────────────────┐
│ 准备首卡                             │
│   要点（直接显示）                   │
│   食材和调味辅料                     │
│     主要食材表                       │
│     调味与辅料表                     │
│   备菜（勾选 / 计时 / 并行提示）     │
│                                      │
│ 卡内纵向滚动，左右滑动切换卡片       │
└──────────────────────────────────────┘
准备   1   2   3   …   N   全部步骤
```

首卡后为现有全部烹饪步骤，每个步骤一张卡，顺序及编号从 1 开始。保留动作、火候、用量、计时、完成标准、提醒和原理。删除独立总览、要点图标、“步骤卡片”切换入口及器具展示区；锅具偏好与实际操作中的工具提示继续作为指南约束和操作内容。

删除成品检查按钮、检查页、检查项、评分与“保存这一餐”。最后一步保留原步骤内容，不追加检查卡、不自动跳转。浏览最后一步、保存心得、计时到点都不代表整餐已完成，不清理计时器。本版不新增整餐完成按钮，历史已完成状态保留。

## 2. 卡片交互

| 操作 | 结果 |
| --- | --- |
| 左右滑动 / 方向键 | 在准备首卡及步骤卡之间切换，首尾不循环 |
| 点击“准备” | 返回首卡，不重置勾选、步骤完成记录或计时 |
| 点击步骤数字 | 直接查看对应步骤，不自动标记完成 |
| 卡片内上下滚动 | 只滚动当前卡片，顶部按钮和底部导航保持可见 |
| 打开全部步骤 | 显示步骤目录；“先备菜 / 查看”定位首卡，选择步骤定位对应卡片 |
| 刷新当前页面 | 恢复查看卡片、备菜勾选、已有完成记录、版本、心得和计时器 |
| 返回 | 预置菜谱回到菜谱大全；AI 菜谱回到开始做菜 |

相邻卡片露边提示左右滑动；非当前卡片通过 aria-hidden / inert 从读屏和键盘焦点顺序中隔离。弹窗限制焦点在内部，关闭后焦点返回触发按钮。保持 320px 至 480px 手机布局，大屏居中；窄屏顶部图标与文字可上下排列。尊重减少动画设置。

## 3. 心得弹窗

顶部按钮顺序固定为“心得 → 问问 AI → 计时器”。心得在准备和任意步骤均可打开。

| 状态 / 操作 | 约定 |
| --- | --- |
| 打开 | 用当前制作记录的 note 初始化独立草稿，旧笔记原文回填 |
| 输入 | 自由多行纯文本，最多 2000 字，显示字数，不解析 HTML |
| 保存心得 | 覆盖当前制作记录 note，空文本允许清空，保存后关闭并反馈 |
| 取消 / 关闭 / 遮罩 / Escape | 放弃未保存草稿，已有记录不变 |
| 再次打开 / 刷新 | 读取最后保存的内容，不恢复已放弃草稿 |
| 保存影响范围 | 仅 note；不改配方、版本、备菜勾选、步骤完成记录、状态或计时器 |
| 再次制作 | 创建新制作记录，note 为空；原记录保留且可查看 |
| 导出 / 删除 | 跟随所属制作记录导出，随指南一起删除 |

心得不是 AI 输出字段，不应因新生成或流程调整被覆盖，不作为菜谱入库或完成烹饪的前提。正式存储失败时应保留编辑草稿并给出重试方式；Demo 的全局存储异常提示仅覆盖本地保存失败，不代表已实现正式事务保存。

## 4. 数据映射

当前 Demo 继续使用 Guide 同时承载菜谱和制作记录，新增 currentCard。正式开发应拆分 Recipe / RecipeVersion 与 CookingSession，心得、查看位置、勾选、完成进度、计时器属于 CookingSession。

| Demo 字段 | 语义 / 正式实现约束 |
| --- | --- |
| Guide.currentCard | 卡片查看位置；0 为准备，1..N 对应烹饪步骤 1..N；属于展示状态 |
| Guide.currentStep | 烹饪步骤索引 0..N-1；选择步骤卡时为 currentCard - 1，回到准备卡时保留原值 |
| Guide.checked | 已勾选的 prep ID，不使用卡片序号 |
| Guide.completed | 已有已完成 step ID；翻卡、保存心得、计时结束都不修改 |
| Guide.note | 本次制作心得，复用旧笔记字段，独立保存；新制作为空 |
| Guide.version / changes | 已确认的流程调整版本与说明；心得不递增版本 |
| Timer.guideId / stepId | 关联制作记录及稳定 prep/step ID；不使用偏移后的轮播序号 |
| Recipe.key / ingredients / prep / steps | 结构化内容，由固定首卡及步骤卡组件呈现 |
| Conditions.cookwares / Recipe.tools | 当前 Demo 保留生成约束及工具元数据，指南中无独立器具区 |
| Recipe.steps[].signal | 每一步完成标准，继续显示；与已删除的 Recipe.signals 无关 |

AI 上下文在 currentCard = 0 时必须使用“备菜阶段”、准备内容和当前计时，不能把保留的 currentStep 当作当前可见步骤；在步骤卡使用当前步骤、已完成记录及计时状态。准备阶段调整从第一条未完成步骤起筛选，已完成步骤保持不变。Demo 仍为规则模拟，正式接入需校验模型返回的受影响步骤 ID。

## 5. 旧入口与本地数据迁移

继续使用 `cookpilot.demo.v1`，不通过清空数据更新界面。

1. 统一指南地址为 `#cook`。旧 `#overview` / `#finish` 在有有效当前指南时转到 `#cook`；无有效指南时回首页，不渲染已删除页面。
2. 已有 currentCard 时限制其范围为 0..N；缺少时由旧 currentStep + 1 恢复旧步骤查看位置。新生成和用户主动打开指南仍显示准备首卡。
3. 保留 note 原文、指南 ID、来源、配方、条件、备菜勾选、completed、版本调整、历史状态和计时器；note 缺失时补空串。
4. 清理旧 Guide.rating、Recipe.signals 和旧 favorite 字段，不把旧评分变成心得，不把独立检查项重新塞进首卡。步骤 signal 保留。
5. 首卡插入不改变 prep/step ID、计时器关联、制作记录 ID 或菜谱版本；不把旧 currentStep 整体加 1。

正式实现应有独立 schemaVersion、可重复执行的迁移及迁移前备份策略。当前 Demo 只在既有键内兼容读取，JSON 导出仍沿用现有格式；不要把 Demo 的结构当作正式导入协议。

## 6. 开发验收

- 所有指南入口直接出现准备首卡，顺序为要点、食材和调味辅料、备菜；器具区与成品检查流程不出现。
- N 个烹饪步骤对应 N+1 张卡，数字 1 始终对应原第 1 步；首尾滑动、目录、键盘和刷新均无偏移。
- 准备勾选和备菜计时可用，回首卡或重新打开指南不清空制作进度。
- 心得按钮在问问 AI 左侧；已有记录可编辑，多行保存、取消、关闭、清空、2000 字限制与刷新恢复正常。
- 心得只改变当前记录 note；另一道菜、原记录与再次制作的新记录互不覆盖。
- 问答区分备菜与步骤阶段，调整只作用于未完成步骤；计时仍绑定原 prep/step ID。
- 旧地址不白屏，旧笔记保留，旧评分/独立检查字段清理；本地导出包含心得且不包含 API Key。
- 320px、390px、480px 下卡片无横向溢出，顶部操作和导航可用；长首卡内部可滚动。
- 生产构建同步更新 demo.html，离线打开、保存心得和刷新恢复可用。

浏览器验证见 tests/demo.spec.ts。正式开发还需在实际手机验证软键盘弹出、长文本编辑、触摸方向竞争、本地存储失败与后台计时恢复。
