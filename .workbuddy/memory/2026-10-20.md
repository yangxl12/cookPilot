## 接入 DeepSeek 网页搜索（commit 78d7a7a）

- 官方 Search/Fetch：`POST https://api.deepseek.com/v1/tools/search`（`/v1/tools/fetch` 抓正文），Bearer 鉴权与 chat 同一个 Key，无需额外开通；按请求计费 5 元/1000 次，**无结果不计费**，`count` 不影响价格（所以给到 5 条）。QPS Search 100 / Fetch 25，账号级。
- 浏览器直连可行：预检 `access-control-allow-origin` 会回显 Origin，`authorization,content-type` 都在 allow-headers 里。实测 400~500ms 返回。
- 实现：`src/services/ai/search.ts` 的 `search()` + `referenceBlock()`；`providers.ts` 加 `searchEndpoint()`（吞掉 `/v1` 和 `/chat/completions` 尾部再拼固定路径）。
- 只接在**完整菜谱生成**前（Home.tsx 的 `select`），推荐与问答不联网。搜索失败/超时 12s/第三方接口一律返回空数组静默降级；只有用户主动取消才抛 AbortError。
- **坑**：summary 是 Markdown 且开头常是铺垫（第一条 1329 字符里前 500 全是"如何卸整只鸡"）。必须先去 `#`/`**`/链接标记、压掉空行，再截断 600 字，否则有用内容被挤没。
- 实测真机：搜索 476ms + 生成 12.7s，一次过校验，用量与真实配比接近。

## 制作问答接入搜索（commit 5165ffe）

- `askCooking(..., signal, references)`；参考块限定用途「仅用于回答品牌、设备、营养等菜谱之外的事实，不得据此修改当前菜谱」。
- UI：`.question-composer` 里加地球按钮 `.web-toggle`（42px，`aria-pressed` 驱动橙色态），默认开启，状态存 `localStorage['cookpilot-question-search']`；非 `api.deepseek.com` 模型不渲染。
- **重要结论：rerank_score 不能用来判断「这个问题需不需要联网」**。实测（纯问题做 query）：流程问题「现在可以下锅了吗」0.58、「鸡蛋凝固了没有」1.40；该搜的「海天金标生抽区别」只有 1.19、「空气炸锅多少度」1.93。分数衡量的是「网页跟 query 多像」，不是「问题是否超出菜谱范围」，所以自动判断必然两头漏。
- 因此改成用户显式开关 + 松过滤 `minScore 1.15`（滤掉 0.5 档废话）。query 用**纯问题**，不要拼菜名——拼了菜名会偏向菜谱页，品牌类问题分数反而更低。
- 真机实测：搜索 515ms + 回答 1.78s（不搜约 1.3s）。带参考的回答没有被带偏（参考是 200℃，模型自己给 180℃ 并说明空气炸锅做不了炒菜）。

## 接口慢排查（未改代码，报告见 docs/接口响应慢排查报告.md）

- 首页推荐实测不慢：端到端 2.4s、接口 1.2–2.1s、提交后 78ms 出气泡、0 长任务；60 轮历史仅 2.1s。v4-pro 4.3s，pro 不传 thinking 11s。
- **生成慢主因：Zod 枚举过窄 + 提示词没写可选值**。`cuisine` 只允许「中式/西式与日式」、`ingredients[].group` 只允许「主料/调味」，模型输出「川菜/腌料」直接 parse 失败，然后整份菜谱重生成（最多 3 次）。三道菜 100% 重试：3 次/15.4s、2 次/7.3s、2 次/11.2s。修提示词或映射/放宽，可省一半时间。
- 搜索 API 实测 0.31–0.36s（代理/直连无差异），占生成时长 2–8%，**不是根因**；风险在串行 + 12s 超时 + 生成路径无开关。建议设置项 + 超时降到 4s。
- 全链路非流式（`client.ts` stream:false）放大了等待感。
- 测速脚本在 `.local/bench*.mjs`、`trace*.mjs`、`check-audit.mjs`（已 gitignore，不提交）。
